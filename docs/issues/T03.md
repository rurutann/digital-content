# [M1][T03][志鳥] 匿名認証とルーム作成・参加APIを実装する

担当：志鳥さん ／ 段階：M1 作成〜参加 ／ 見積もり：4ポイント  
着手順：志鳥さんの3番目（前は[T02](T02.md)、次は[T04](T04.md)）

## この段階のゴール

M1が終わると、**ルームを作り、別のスマホでQRを読み取って同じルームに入れる**状態になります。

## 目的

登録なしでルームを作成・参加できるようにし、他のEdge Functionが使う共通処理を用意する。

## 担当ファイル

`frontend/src/features/auth/`、`features/rooms/`、`lib/supabase.ts`、`backend/supabase/functions/create-room/`、`join-room/`、`functions/_shared/`（auth.ts・cors.ts・errors.ts）

## 作業内容

- [ ] 匿名サインインと、再アクセス時のセッションの引き継ぎを作る
- [ ] ルーム作成（期限＝作成から24時間）を作る
- [ ] URLからの参加を作る（同じ人が何度参加しても重複しないようにする）
- [ ] `useRoom`で、読み込み中・正常・存在しない・期限切れの状態を返す
- [ ] `_shared/`に、認証・参加者の確認・CORS・エラー形式の共通処理を作る

## 完了条件

- [ ] 登録なしでルームを作成・参加できる
- [ ] 同じ端末・同じブラウザなら、有効期限内に同じユーザーとして再アクセスできる
- [ ] 不正なURL・存在しないルーム・期限切れを区別して返す

### 注意

- roomIdは推測できない値（UUIDなど）にしてください。連番は使わないでください。
- 匿名ユーザーは**ブラウザごとに別人**として扱われます。同じ人でもSafariとChromeでは別の投稿者になります。削除権限に関わるので、全員に共有してください。
- `_shared/`を変更すると斎藤さんの関数にも影響します。変更するときは事前に知らせてください。
