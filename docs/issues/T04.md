# [M1][T04][志鳥] 参加者だけが閲覧・投稿できる権限（RLS）を設定する

担当：志鳥さん ／ 段階：M1 作成〜参加 ／ 見積もり：3ポイント  
着手順：志鳥さんの4番目（前は[T03](T03.md)、次は[T05](T05.md)）

## この段階のゴール

M1が終わると、**ルームを作り、別のスマホでQRを読み取って同じルームに入れる**状態になります。このIssueは、M2の投稿・閲覧の前提になります。

## 目的

ルームの参加者だけが、そのルームのデータを読み書きできるようにする。

## 担当ファイル

`backend/supabase/migrations/`のRLS用SQL、`tests/db/`

## 作業内容

- [ ] rooms・参加者・photosにRLSを設定する
- [ ] 「このユーザーはこのルームの参加者か」を判定するSQL関数を作る（例：`is_room_member(room_id)`）
- [ ] 参加者だけが閲覧・投稿できるようにする
- [ ] 2人の異なる匿名ユーザーでテストを書く

## 完了条件

- [ ] 未参加のユーザーは、ルーム内のデータを取得できない
- [ ] 参加者は、写真の一覧を取得できる
- [ ] 2人のユーザーを使ったテストが通る

### 注意

- テーブルを追加したら、RLSを有効にし忘れていないか確認してください。
- service_role keyはRLSを無視します。Edge Functionでservice_roleを使う場合は、関数の中で自分で権限を確認する必要があります（`_shared/`の共通処理を使う）。
- 期限切れの拒否は[T05](T05.md)で追加します。
