# [M0調査][K01][斎藤] 画像形式（特にHEIC）を技術検証し、表示方針を決める

担当：斎藤さん ／ 段階：M0〜M1（調査） ／ 見積もり：2ポイント  
着手順：斎藤さんの1番目（次は[K02](K02.md)）

## この調査が必要な理由

HEICはiPhoneの標準形式ですが、AndroidやChromeでは表示できません。**この結果によって、DBの列（[T01](T01.md)）、一覧の表示（[S03](S03.md)）、投稿の処理（[K02](K02.md)）の作り方が変わります。** M0のうちに方針を出してください。

## 担当ファイル

`docs/storage.md`

## 作業内容

- [ ] iPhoneのSafariでファイルを選んだとき、実際に送られる形式を確認する（HEICのまま送られるか、JPEGに自動変換されるか）
- [ ] JPEG・PNG・HEICを、iPhoneとAndroidのブラウザで表示できるか確認する
- [ ] 表示方針を決める（例：原本はそのまま保存し、表示用にJPEGを用意する／MVPではHEICを表示しない旨を表示する）
- [ ] 1枚あたりの実際のファイルサイズを測り、100枚・500MBの制限が妥当か確認する
- [ ] 結果と方針をdocs/storage.mdに書く

## 完了条件

- [ ] 形式×端末ごとの、投稿・表示・保存の結果が記録されている
- [ ] HEICの表示方針が決まり、関係者に伝えてある
