## この調査が必要な理由

一括保存は、ICHIEの一番の売りです。しかし、iPhoneとAndroidで挙動が大きく異なります。**この結果によって、斎藤さんのダウンロードAPI（[K03](K03.md)）の作り方と、JSZipを追加するかどうかが決まります。** できるだけ早く結論を出してください。

## 担当ファイル

`docs/save-verification.md`（新規作成。結果を記録する）、`frontend/src/features/photos/utils/download.ts`（試作）

## 作業内容

- [ ] iPhone（Safari）とAndroid（Chrome）で、Web Share API（`navigator.canShare`・`navigator.share`）にファイルを渡して保存を試す（1枚・複数枚）
- [ ] 一度に渡せる枚数とサイズの目安を調べる
- [ ] Web Share APIに対応していない環境で、`<a download>`による保存とZIP（JSZip）での保存を試す
- [ ] JPEG・PNG・HEICそれぞれで、保存先（写真アプリかファイルアプリか）を確認する（HEICは斎藤さんと一緒に確認する）
- [ ] 採用する方式を決め、結果を端末×方法の表にまとめる

### 注意

- Web Share APIは**HTTPSでしか動きません**。[S01](S01.md)の公開URLか、HTTPSで開ける検証用ページで試してください。
- `navigator.share`は、**タップした直後に呼ばないと**失敗することがあります。画像のダウンロードに時間がかかってからだと失敗する場合があるので、「先に画像を取得しておき、その後のボタン操作で共有する」流れも試してください。
- 「必ず写真アプリに保存される」とは約束できません。端末ごとの違いを記録してください。
